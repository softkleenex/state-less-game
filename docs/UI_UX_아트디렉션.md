# STATE//LESS UI/UX 아트 디렉션

## 확정 방향

**MEMORY:// LOCAL ARCHIVE — 버려진 브라우저 로컬 기억 보관소**

이 게임의 화면은 미래형 해킹 터미널이 아니라, 한 출처(origin)에 남은 쿠키와 브라우저 흔적을 MORI가 분류하는 개인 기억 일지다. 모든 장식은 쿠키·탭·방문·기억 조각이라는 실제 게임 규칙에서 출발한다.

## 기존 화면에서 바꾼 이유

- 네온과 유리 패널 중심의 사이버펑크 UI는 다른 SF 게임에도 붙일 수 있어 고유성이 약했다.
- Cookie Store가 코드에는 있었지만 첫 화면만 보면 핵심 규칙을 알기 어려웠다.
- 캐릭터가 게임 속 역할보다 일반적인 사이버펑크 미소녀에 가까워 UI와 별도로 보였다.

새 방향에서는 캐릭터를 먼저 꾸미지 않는다. UI에 MORI가 맡을 자리와 상태를 만든 뒤 그 규격에 맞춰 캐릭터를 제작한다.

## 설정과 UI의 연결

| 게임 설정 | 화면 표현 | 플레이어가 이해할 내용 |
|---|---|---|
| 한 출처에만 남는 기억 | `memory://local/` 주소와 `THIS ORIGIN ONLY` | 다른 사이트나 개인정보를 읽지 않는다 |
| 쿠키 일지 | 방문·런·조각·보존·점수를 적은 색인 카드 | 재방문 진행도가 다음 문제의 소재가 된다 |
| 가짜 신호 침입 | 6개 슬롯 중 무작위 위치에 rose `✕` 또는 cyan `◆` 신호가 짧게 켜짐 | 읽는 게 아니라 색과 기호로 즉시 구분해야 한다 |
| 반응 속도 게임 | 신호 등장 간격·지속시간·동시 개수가 60초 내내 escalate | 판단 난이도가 아니라 반응 속도·동시 처리 부담이 오른다 |
| 코어 방어 | 슬롯 주변 signal-field와 `CORE INTEGRITY` 3칸 | 진짜를 잘못 건드리면 코어가 다친다 |
| 기억 보존 | amber 보존 표시 | 오래 남길 선택과 획득한 조각 |
| 제한 자원 | `ARCHIVE LENS` 잔량과 `F` 키 | 4초 동안 신호를 느리게 만들지 판단한다 |
| 위험 선택 | `DEEP VERIFY`와 amber·rose 상태선 | 5초 동안 2배 점수·2배 손실을 걸지 선택한다 |
| 콤보 | `COMBO` 배수와 MORI 상태 | 연속 정화가 점수 배율로 이어진다 |
| 런 강화 | 15/30/45초 지점의 강화 카드 2택1 오버레이 | 순발력 말고도 이번 런을 어떻게 플레이할지 스스로 정한다 |
| 런별 요청 | `MORI REQUEST` 코드·진행도·600점 보상 | 다음 판에서 무엇을 다르게 노릴지 한 문장으로 제시한다 |
| 오염·삭제 | rose 정정 표시 | 오답, 불안정 결말, 삭제 위험 |
| 검증 완료 | emerald 검수 표시 | 정답과 확정된 기록 |
| MORI | 큰 인물 파일 + 작은 상태 슬롯 | 세션 검증 AI이자 플레이 반응 주체 |

## 색상 역할

새 색을 늘리지 않고 기존 디자인 토큰만 사용한다.

- `slate-950 / slate-900`: 보관소 잉크와 바탕
- `slate-100 / slate-200`: 종이와 본문
- `cyan-300`: 색인선, 현재 위치, 키보드 포커스
- `amber-300`: 보존 기한, 선택 강조, 캐릭터 식별점
- `rose-400`: 오염, 삭제, 상처
- `emerald-300`: 검증 완료

강한 네온 광원과 넓은 글래스모피즘은 사용하지 않는다. 얇은 괘선, 사각 카드, 하프톤, 제한된 상태색을 사용한다.

신호의 진짜/가짜 구분도 새 색을 추가하지 않고 기존 상태색을 그대로 재사용한다: 가짜 신호는 rose(오염·삭제와 동일 — "위협, 지워야 함"), 진짜 신호는 cyan(색인선·현재 위치와 동일 — "안전, 그대로 둠"). 가짜를 정화하면 슬롯 테두리가 emerald로 잠깐 밝아지고, 진짜를 잘못 클릭하면 rose 오답 상태선과 같은 흔들림(jolt) 애니메이션을 재사용한다 — 새 모션 언어를 만들지 않는다.

슬롯의 남은 시간 표시도 새 컴포넌트를 만들지 않고 기존 conic-gradient 링 방식을 그대로 재사용한다. 다만 이번에는 링이 얇은 고리로 보이도록 `mask`를 추가해, 안쪽의 진짜/가짜 아이콘과 바깥쪽 테두리 색을 가리지 않게 했다.

## 화면별 계층

### 인트로

- 왼쪽: 플레이어의 현재 일지 요약
- 오른쪽: `memory://local/ledger/...` 위치와 MORI의 큰 인물 파일
- 첫 방문: 세션/7일 쿠키 정책을 색인 카드로 선택
- 재방문: 이전 결말과 기억 조각을 MORI가 먼저 언급

### 플레이

- 플레이 시작과 함께 소개 열을 접고 게임 패널을 중앙 최대 1120px로 확장해, 랜딩 페이지가 아니라 한 판의 전용 무대로 전환
- 주소: `memory://local/core/watch`
- 우측 상단 `MORI STATE` 슬롯은 상시 상태를 전달하고, 정화·오클릭 순간마다 MORI의 표정과 대사가 함께 바뀐다
- 중앙: signal-field — 6개 슬롯이 2행 3열 고정 위치에 배치되고, 각 슬롯에 번호 키(1~6) 힌트가 항상 붙어 있다. 신호가 뜨면 rose `✕`(가짜) 또는 cyan `◆`(진짜) 아이콘과 남은 시간을 나타내는 conic-gradient 링이 함께 표시된다
- 정화는 클릭 또는 번호 키로 즉시 이뤄진다 — 가짜 슬롯을 맞히면 emerald로 잠깐 밝아지고 점수 팝업이 뜨며, 진짜 슬롯을 잘못 누르면 즉시 코어 무결성이 줄고 rose 흔들림으로 되돌아온다. 가짜를 그냥 놓치면(시간 초과) amber로 잠깐 바뀔 뿐 무결성은 줄지 않아, "잘못 누른 것"과 "놓친 것"의 무게가 시각적으로도 다르게 느껴진다
- 잔여시간이 30% 미만인 가짜 신호는 점멸이 amber→rose, 900ms→420ms로 빨라져 "이제 정말 급하다"는 신호를 색과 속도로 함께 전달한다
- signal-field 위: `DEEP VERIFY`의 2배 점수·2배 손실·`D` 키, 활성화 중에는 남은 시간을 한 줄에 항상 표시
- 상단 상태선: 정화/오클릭/놓침 수·`CORE INTEGRITY`·`COMBO`·남은 `ARCHIVE LENS`를 표시
- 하단 상태줄: 순환하는 `MORI REQUEST`와 진행도·보상을 표시
- 남은 시간이 20% 미만이면 signal-field 테두리가 rose로 바뀌어 "런이 곧 끝난다"는 압박을 전달
- 15/30/45초 지점: signal-field 위에 반투명 오버레이가 덮이고 강화 카드 2장이 뜬다. 클릭 또는 번호 키(1/2)로 하나를 고르면 게임이 다시 흐르고, 고른 강화 이름이 상태줄에 계속 표시된다
- 60초 타이머 종료 또는 코어 무결성 0 중 먼저 도달하는 조건으로 즉시 결과 화면으로 전환 — 별도의 "다음 웨이브" 버튼이나 중간 정지 화면이 없다
- 가짜 신호의 점멸(scale pulse)만 실시간 애니메이션이라 `prefers-reduced-motion`에서는 이 점멸만 정지시키고, 카운트다운 링과 판정 가능 여부는 동일하게 유지한다

### 결과

- 주소: `memory://local/ending/{ending}`
- MORI 큰 인물 파일 재등장
- 점수·랭크·진실·조각을 검수표 형태로 표시
- 성공 시 새 MORI 기록을 일지 카드로 공개하고, 실패 시 다음 기록이 잠겼음을 표시
- 저장과 삭제의 위험 차이를 명시

## 캐릭터 자산 슬롯

| 슬롯 | 권장 원본 | 실제 표시 | 용도 |
|---|---:|---:|---|
| 인트로·결과 전신 | 2048×3072 PNG | 최대 약 350×570px | 실루엣과 복장 전달 |
| 플레이 반응 흉상 | 1600×1600 PNG | 상태 슬롯 최대 50×52px, 판정 컷인 최대 96×150px | 상시 상태와 판정 표정을 즉시 구분 |
| 웹 최적화본 | WebP alpha | 원본 크기에 맞춤 | 빠른 정적 웹 로드 |

전신 이미지를 모든 상황마다 다시 생성하지 않는다. 전신은 모델 기준표 1장으로 유지하고, 플레이 반응은 같은 흉상 원본의 표정·손·소품 일부만 마스킹 편집한다.

## 상호작용 원칙

- 키보드 또는 마우스 한 종류만으로 모든 흐름을 끝낼 수 있어야 한다.
- hover만으로 정보를 전달하지 않는다. 선택은 포커스·테두리·텍스트 상태가 함께 바뀐다.
- 모든 주요 클릭 영역은 최소 44px 높이를 유지한다.
- 장식용 주소창과 탭은 실제 조작 요소처럼 보이지 않게 버튼 역할을 주지 않는다.
- 이미지에 width/height를 명시해 레이아웃 이동을 막는다.
- `prefers-reduced-motion`에서는 전환과 회전 효과를 사실상 제거한다.
- 모바일·태블릿에서는 플레이 패널을 소개보다 먼저 배치해 첫 화면에서 바로 게임을 시작할 수 있게 한다.
- 모바일에서는 MORI의 존재감은 유지하되 장식 오브와 전신 슬롯 높이를 줄이고, 소개 정보는 플레이 패널 뒤의 보조 문맥으로 재구성한다.

## 피해야 할 표현

- 의미 없이 빛나는 네온 회로와 HUD
- 가짜 터미널 명령어를 읽게 하는 화면
- 모든 요소가 둥근 카드인 대시보드
- 캐릭터와 관계없는 홀로그램 장식
- 불필요한 글리치, 흔들림, 장시간 스캔 애니메이션
- 개인정보를 읽는 것처럼 오해할 수 있는 브라우저 정보

## 현재 구현 상태

- `memory://local/` 상태 경로 구현
- `LOCAL MEMORY ARCHIVE` 일지 프레임 구현
- 세션 카드 기반 3구역(진짜/가짜/손상) 판정 UI 구현
- 세션 카드 내부 2열 비교(`MORI의 기록` / `이 세션의 주장`) 구현 — 별도 참고 패널 없이 카드 자체에서 대조 판단이 끝나며, 환경이 실제로 바뀌면(뷰포트, 탭 이탈, 네트워크 등) `MORI의 기록` 값도 즉시 갱신됨
- MORI 상황 상태를 위한 `data-mori-state` 및 플레이 반응 슬롯 구현
- 플레이·결말 몰입 모드, 웨이브별 목표/경과 표시, 판정 컷인, 직접 다음 웨이브 진행 구현
- 브라우저 10개 신호에 쿠키 진행도 `SHARDS·RUNS·RETENTION·BEST`를 더한 14개 신호 소재 구현(각 신호의 참/거짓/판독불가 텍스트가 세션 주장 줄의 내용이 됨)
- `ARCHIVE LENS`(정답 구역 확인), 선택형 승부수 `DEEP VERIFY`(5초 버스트), 2배 보상의 `FINAL CORE`, `SYNC LINKED`, 3연속 컴백 `SYNC RECOVERY`, 3종 순환 `MORI REQUEST`, 성공 전용 조각 보상과 6개 MORI 기록 구현
- `캐릭터/MORI_상황별_캐릭터_설계.md` 기준으로 전신 기준표 1장과 17개 상황별 흉상을 모두 제작해 실제 게임에 연결 완료. 인물 파일·상태 슬롯·판정 컷인이 상태마다 실제로 다른 이미지를 표시함
- 예전에는 이미지가 1장뿐이라 CSS로 크롭·채도를 억지로 바꿔 표정 차이를 흉내냈으나, 실제 이미지가 생기면서 그 CSS는 제거하고 `object-fit: cover` 기반으로 정리함
- 일지·터미널 텍스트(세션 코드, 타이머, 점수 등)에 JetBrains Mono(OFL 라이선스)를 자체 호스팅으로 추가해 OS별 폰트 렌더링 차이를 없앰
- "게임 같지 않고 듀오링고 같다"는 피드백에 이어, 실제 플레이 후 "여전히 재미없다"는 재피드백을 받고 재미 이론(MDA·Koster·Swink·Flow·Meaningful Play, 자세한 근거는 `AI_활용_기술.md` 참고)에 기반해 핵심 메커닉 자체를 `SIGNAL TRIAGE`(흐르는 칩을 실시간으로 3구역에 분류)로 전면 교체함. "세 선택지 중 하나를 고르고 타이밍 미터로 확정"하던 정적 구조에서 "계속 흘러 들어오는 칩을 멀티태스킹으로 분류"하는 구조로 바뀌며 라운드 종류(6종 규칙)와 `SIGNAL LOCK` 타이밍 미터, 그 근간이던 Pretext 문서 리플로가 모두 제거됨. 라운드가 바뀌어도 동일했던 통일 지시문(`prompt`/`instruction`) 원칙은 웨이브 단위로 그대로 유지. 무결성·SYNC·ARCHIVE LENS·DEEP VERIFY·MORI REQUEST·기억 조각 시스템은 값 입력원만 바뀌었을 뿐 그대로 유지
- "쿠키 해석이라는 컨셉 자체가 경쟁력 있어 보이지 않는다"는 피드백에 따라 스토리 프레임을 재검토함. 메커닉과 색상·컴포넌트는 전혀 바꾸지 않고, "기억 관리 AI가 기억을 정리한다"는 프레임을 "누군가 당신인 척 이 브라우저에 들어오려 하고, 세션 검증 AI MORI가 진짜/위조/판독불가 신호를 실시간으로 가려낸다"로 교체. 이미 있던 `OTHER SELF`(다른 탭 감지) 신호와 MORI 대사("같은 페이지가 하나 더 있어. 어느 쪽이 진짜 너지?")가 이 프레임과 정확히 맞아떨어져, 설정을 새로 쓰지 않고 이미 있던 서사를 인트로 앞자리로 끌어옴. `TRIAGE LANE` 세 구역의 표시 라벨만 `TRUE`/`FALSE` → `VERIFIED`/`SPOOFED`로 교체(내부 데이터 값과 색상 매핑은 무변경)
- 실제 플레이 후 "모르면 못 하는 단순 반복이고, 알아도 대조 작업일 뿐"이라는 지적을 받고 핵심 메커닉을 다시 전면 교체함(`SIGNAL TRIAGE` → `SESSION AUDIT`, 심문관형 판단). 흐르는 칩을 실시간으로 3구역에 분류하던 방식에서, 세션 하나(2~3개의 사실이 결합된 주장)를 한 번에 제시하고 제한 시간 안에 판정하는 방식으로 전환. 핵심 차이는 판단 자체의 복잡도 — 결합된 사실 중 정확히 한 줄만 거짓이거나 판독 불가라 모든 줄을 확인해야 하고, 웨이브가 오를수록 결합되는 사실 개수(2→3)와 판정 시간(13초→7초)이 함께 변해 "속도"뿐 아니라 "판단 복잡도" 자체가 스킬 천장을 만든다. 위조를 진짜로 승인하는 실수(무결성 -2)와 진짜를 위조로 오인하는 실수(무결성 -1)에 비대칭 대가를 둬 확신 없는 상황에서의 딜레마를 만듦. `TRIAGE LANE`/`triage-zones` 컨테이너와 `VERIFIED`/`SPOOFED`/`CORRUPTED` 색상 매핑, 무결성·SYNC·ARCHIVE LENS·MORI REQUEST·기억 조각 시스템은 그대로 재사용 — 웨이브 내부 채점 모델만 교체됨
- `SESSION AUDIT`를 실제로 검토한 뒤에도 "재밌는지 모르겠다"는 재차 지적을 받음. 원인은 `LIVE SIGNAL` 패널이 모든 사실의 정답을 상시 노출하는 "항상 맞는 참고표"였다는 것 — 판단이 아니라 참고표와 주장을 맞춰보는 교정(proofreading) 작업에 가까웠음. "이미 검증된 유명 게임을 레퍼런스로 가져오자"는 요청에 따라 Papers, Please의 "두 서류를 나란히 놓고 교차 대조"하는 방식을 채택. `LIVE SIGNAL`이라는 별도 패널을 없애고, 그 근거 데이터를 세션 카드 안으로 옮겨 `MORI의 기록`(항상 사실)과 `이 세션의 주장`(정확히 한 줄만 다르거나 손상)을 같은 카드에 2열로 나란히 배치함. 플레이어의 과제가 "어딘가의 정답표 열람"에서 "두 나란한 기록 사이 스팟더디퍼런스"로 바뀜 — 판정 3버튼·비대칭 페널티·웨이브 escalation·메타 진행 전체는 무변경. 이어 "용어와 단어는 쉬운 걸로" 요청에 따라 가장 자주 보이는 판정 버튼 3개만 `VERIFIED`/`SPOOFED`/`CORRUPTED` → **진짜**/**가짜**/**손상**으로 교체(내부 데이터 값·단축키·색상 매핑은 무변경). `ARCHIVE LENS`/`DEEP VERIFY`/`SYNC`/`MORI REQUEST`/`SESSION AUDIT`/`VERIFIED GATE` 등 나머지 영어 라벨은 이번 범위에서 유지
- Papers, Please식 대조로 전환한 뒤에도 참여자가 "여전히 게임 형태를 띠고 있다고 보기 어렵다"고 재평가하며 사전과제 자체를 처음부터 다시 만드는 것까지 검토를 요청함. NAN 2026 사전과제 접수 마감(8/10)이 3일 남은 시점이라 완전 신규 개발은 빌드·영상·문서를 전부 새로 완성해야 하는 리스크가 컸음. 코드베이스를 다시 검토한 결과 `game-logic.js`(웨이브 곡선·채점·무결성·`ARCHIVE LENS`·`DEEP VERIFY`·`MORI REQUEST`·기억 조각·결말 판정)는 전부 DOM에 의존하지 않는 순수 함수라 그대로 재사용 가능하다고 판단해, "판정 자체를 다시 만들지 않고 판정에 도달하는 방식만 교체"하는 절충안으로 범위를 좁힘. 세션 카드가 자동으로 나열되던 `SESSION AUDIT`에, 룸에 배치된 최대 5개 터미널이 무작위·동시에 켜지고 요원을 직접 이동시켜 도착해야만 카드가 열리는 이동+도킹 레이어를 얹음. 여러 터미널이 동시에 켜지는 웨이브에서는 "어디부터 갈지" 우선순위 판단이 실시간 압박으로 추가되어, 텍스트 대조 이전에 공간적·시간적 결정이 먼저 필요해짐.
- 이동은 방향키 가속·감속(관성 있는 아케이드 물리)과 터미널 클릭·탭에 의한 자동 이동(같은 물리 루프가 목표점까지 유도) 두 경로를 완전히 동등하게 지원해, 키보드/마우스 단독 완주 원칙을 유지함. 터미널은 idle → pending(점멸+카운트다운) → active(도킹, cyan 전환) → resolved(판정 결과 색) → idle로 순환하며, 대기열이 남아 있으면 즉시 같은 슬롯에 다음 세션을 이어 배정함. `WAVE_CONCURRENT_TERMINALS`([1,2,2,3,3,4])를 새로 추가해 웨이브가 오를수록 동시 대기 터미널 수가 늘도록 했고, 이동·도착 시간을 흡수하도록 `WAVE_SESSION_TIMER_MS`를 웨이브당 소폭(1.5~2초) 늘려 재조정함 — 그 외 무결성·SYNC·비대칭 페널티·기억 조각 시스템은 값 하나도 건드리지 않음.
- 헤드리스 브라우저로 실제 검증: 클릭 이동이 목표 터미널까지 정확히 도킹하는지, 도킹 시 세션 카드가 열리고 판정 후 970점 등 정상 채점이 되는지, 판정 완료 터미널이 짧게 결과색을 보인 뒤 대기열의 다음 세션을 즉시 이어받는지, 무결성이 0이 될 때까지 오답을 반복하면 `NULL` 랭크로 결과 화면에 도달하는지, 터미널에 아예 도킹하지 않고 카운트다운을 흘려보내면 무결성 손실 없이 "놓침" 1회만 기록되는지, 방향키만으로 화면 위 아바타 좌표가 실제로 이동하는지까지 확인 — 콘솔 에러 0건.
- 룸이 시각적으로 비어 보인다는 자체 판단에 따라 오픈소스·레퍼런스를 점검함. 장르 레퍼런스로 `FTL: Faster Than Light`(다중 시스템 동시 위기)와 `Keep Talking and Nobody Explodes`(다중 모듈 동시 경고)를 확인하고, 화면 흔들림 오픈소스 라이브러리는 검토 후 "새 런타임 의존성보다 기존 자산 재활용이 낫다"고 판단해 채택하지 않음. 대신 `src/audio.js`에 정의돼 있었지만 어디서도 호출되지 않던 `warning()`을 터미널이 새로 켜질 때의 경보음으로 연결하고, 잔여시간 30% 미만 구간에서만 터미널 점멸을 amber→rose·900ms→420ms로 전환하는 `data-urgent` 속성을 추가함. 두 변경 모두 새 사운드·색상·애니메이션 원리를 만들지 않고 기존 토큰(`--warm`/`--danger`, `terminal-pulse`)만 재사용.
- 모바일 뷰포트(390px)에서 헤드리스 스크린샷으로 룸 레이아웃을 확인하는 과정에서, `.terminal-ring`이 얇은 진행 링이 아니라 꽉 찬 파이 모양으로 렌더링되어 amber(대기)/cyan(도킹) 상태 구분을 가리는 문제를 발견함. `mask: radial-gradient(...)`로 링 중심을 도려내 얇은 고리로 바꿈 — 새 색상·시각 언어 추가 없이 기존 conic-gradient를 얇게 보이도록만 수정.
- 이동+도킹 재설계를 실제로 플레이해본 뒤 "게임처럼 느껴지지 않는 건 문답 부분이고, 기록(텍스트)을 대조하는 게 게임이라기보다는 문서작업에 가까워 보인다"는 재차 지적을 받음. 이동이라는 포장을 아무리 바꿔도 핵심 조작이 "읽고 비교하고 클릭"인 이상 근본적으로 반응형 조작이 아니었다는 뜻으로 진단하고, "아케이드인데 메타적 요소를 가진 아케이드나 미니게임은 어때?"라는 참여자의 요청에 따라 두 후보(SIGNAL STRIKE — 두더지잡기형 리플렉스 / CORE DEFENSE — 미사일 커맨드형 요격)를 스케치해 제시함. 구현 난이도가 낮고(이동·충돌 로직 불필요) 반응형 조작이라는 목표가 가장 분명한 **SIGNAL STRIKE**를 선택받음.
- 판정 자체(읽기·대조·분류)를 완전히 폐기하고, "화면에 뜬 신호가 색·기호로 즉시 구분되는 가짜인지 진짜인지 보고 손이 먼저 나가야 하는" 반응형 조작으로 교체함. 6개 고정 슬롯에 무작위로 rose `✕`(가짜)/cyan `◆`(진짜) 신호가 짧게 켜지고, 가짜만 클릭·번호 키로 정화하며 진짜는 그대로 흘려보내는 단일 60초 런으로 전환. 이동+도킹 레이어에서 이미 쓰던 고정 슬롯·conic-gradient 링·클릭+번호 키 이중 입력 패턴을 그대로 재사용해, "터미널까지 걸어가기"만 제거하고 "슬롯에 뜬 걸 즉시 처리하기"로 압축함.
- 웨이브(6판) 구조 자체를 폐기하고 시간 기반 단일 escalation(등장 간격 900ms→340ms, 지속시간 1.45초→0.7초, 동시 개수 1→4)으로 전환. `ARCHIVE LENS`는 "판정 공개"에서 "4초 슬로모션"으로, `DEEP VERIFY`는 "다음 판정 1회 웨이브"에서 "5초 2배 윈도"로 재정의했지만 두 자원 모두 충전 수 계산(`getArchiveLensCharges`)과 위험/보상 대비 구조는 그대로 재사용. 쿠키 메타 진행(방문·런·최고점수·기억조각·MORI 6개 로그)은 값 하나도 건드리지 않음.
- 헤드리스 브라우저로 실제 검증: 가짜 신호를 클릭하면 정화·점수·콤보가 오르는지, 진짜 신호를 클릭하면 코어 무결성이 줄고 콤보가 끊기는지, 오클릭 3회로 무결성이 0이 되면 `NULL` 랭크로 결과 화면에 도달하는지, `ARCHIVE LENS`·`DEEP VERIFY`를 키보드(F/D)로 활성화하면 상태 표시와 2배 채점이 실제로 반영되는지, 번호 키(1~6)로도 클릭과 동일하게 정화되는지 확인 — 콘솔 에러 0건.
- SIGNAL STRIKE를 실제로 플레이해본 뒤 "재밌냐? 단순히 순발력 말고는 무슨 의미가 있는지 모르겠다"는 지적을 받음. 진단: 콤보·`ARCHIVE LENS`/`DEEP VERIFY` 타이밍이라는 얕은 선택은 있었지만, 매 순간의 신호 처리 자체에는 트레이드오프가 전혀 없어 "본 대로 반응하는" 것 외에 결정할 게 없었음. "게임적인 요소나 메타적인 요소를 추가해보자"는 요청에 따라, 완전한 장르 교체 대신(6번째 재설계는 마감 리스크가 큼) 기존 반응형 루프 위에 가벼운 로그라이트 강화 선택을 얹는 절충안을 제시하고 채택됨 — 15초·30초·45초 지점마다 게임을 잠깐 멈추고 강화 카드 2장 중 1장을 고르게 함.
- 강화 6종을 모두 순수 상승이 아니라 트레이드오프로 설계함(콤보 특화: 콤보 보너스 +50%지만 오클릭 손실 +1 / 안전한 손: 오클릭 손실 -1이지만 점수 -10% / 여유 확보: 지속시간 +20%지만 동시 개수 +1 / 고위험 배팅: DEEP VERIFY +3초지만 발동 시 진짜 신호 강제 추가 등장 / 렌즈 숙련: 충전 +1이지만 지속시간 -1초 / 코어 보강: 즉시 회복 1칸이지만 콤보 보너스 -20%). 6종을 2개씩 3번에 나눠 제시해 한 런에 3종만 겹치지 않게 갖도록 설계 — 런마다 다른 빌드가 되도록 하는 것이 "메타적 의미"의 핵심.
- 강화 픽 중에는 게임을 완전히 정지시키고(웨이브 이전 재설계에서 쓰던 "탭 이탈 시 타임스탬프를 멈춘 만큼 밀어 넣는" 트릭을 재사용), 픽이 끝나면 정지했던 시간만큼 모든 신호의 마감시각과 다음 스폰 시각을 그대로 밀어 넣어 60초 총 플레이 시간이 그대로 보존되도록 함 — 새 일시정지 로직을 만들지 않고 이미 있던 것을 재사용.
- 헤드리스 브라우저로 검증: 강화 픽이 정확히 15/30/45초 경과 시점에 열리는지, 3번의 픽이 서로 겹치지 않는 6종을 정확히 소진하는지, 번호 키(1/2)로 고르면 오버레이가 닫히고 상태줄에 강화 이름이 남는지, 두 번의 정지-재개를 거쳐도 60초 런이 정확히 끝나 결과 화면에 도달하는지 확인 — 콘솔 에러 0건.
- "정말 게임처럼 느껴지게" 발전시켜 달라는 요청에, 6개 슬롯이 원래 비워 두던 signal-field 정중앙에 `core-orb`를 추가함 — 무결성에 따라 cyan→amber→rose로 변하며 계속 숨 쉬듯 펄스하고, 정화·오클릭마다 커지거나 흔들리며 반응하는 실체 있는 방어 대상을 만듦. 오클릭 시 화면 전체 흔들림, 콤보 4/8/12마다 코어 위로 튀는 "COMBO ×N!" 콜아웃(과 죽어 있던 `audio.core()` 재활용), 결과 화면 점수 카운트업과 랭크(S=금빛/NULL=rose) 스탬프 등장까지 더해 Game Feel(Steve Swink) 원칙을 메커닉 변경 없이 순수 피드백 레이어로만 적용함. 전부 `prefers-reduced-motion`에서 애니메이션은 끄고 색상 정보만 유지.
